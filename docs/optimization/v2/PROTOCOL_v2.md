# 准确率优先的最终阈值协议 v2

协议 ID：`eot_accuracy_first_threshold_v2`。2026-09-16。
机器规则：`outputs/optimization/v2/protocol/rules.json`。
顺序入口：项目根目录 `阈值优化TODO_v2.md`。

## 1. 目标、适用范围与研究性质

在相同模型概率上，让最终阈值优先提高正确人数，同时在选择集上不降低相对 R1 的 TP。R1 是该模型以早期阈值进行最终分类的参考，不是旧 R2。此约束不保证测试集准确率或召回率不下降，不承诺保留 v1 OPT 的召回率，也不使用任何历史测试百分比作为搜索目标。

这是查看过 v1 测试结果后制定的补充探索。复用数据、模型及概率而非声称新训练；后续外层评价只描述冻结流程，不能恢复测试集的独立性。独立确认需要新的保留数据。本次不扩大参数搜索，不引入学习率、loss、概率校准或其他候选。

## 2. 完全固定的实验主体与只读复用

原始数据、清洗、encoder revision、embedding 顺序、256 帖/256 tokens、时间归一化、EOT 网络、mask、有效前缀、用户级 loss、五折划分、训练参数和最佳 epoch 全部保持不变。新增训练次数和新增模型推理次数均为零。

唯一模型为 v1 最终选中的 A；三种子固定为 42/43/44，在同一用户/前缀上算术平均概率，不按成绩选种子。五折已验收全部回退 A/R2，因此不存在重新挑选 loss 的步骤。

内部验证复用 `v1/stability/evaluation/outer_f/inner_j/A/ensemble/{final,prefix}.parquet` 及 `ensemble.json`，追溯种子 42 的 screening 和 43/44 的 stability 预测/运行/checkpoint。不得以 whole-H 的既有阈值评价本协议的 H 子折。

实际校准复用 `v1/final/calibration/outer_f/bundle/`，每折 91 人、10 名正类。最终早期阈值来自 `v1/final/locks/outer_f.json` 的 R1；不得重新选择部署早期阈值。

外层最终评价只在 V04 读取 `v1/final/evaluation/` 的冻结概率/决策，复用不改变原文件。旧结果可以被原封不动作为历史比较对象，不能参与本轮选择。

## 3. 准确率优先选择规则（唯一新策略）

选择集 Q 只能是当前 H 的拟合半集，或当前外层 C。取用户最后有效概率 p，以 `p >= t` 判正，继续调用原有效前缀/指标实现。

网格直接复用 `eot.metrics.DEFAULT_THRESHOLD_GRID`：201 个点，0–1、步长 0.005；不得用另一浮点生成方法悄悄改变边界。令 r 为 Q 的参考早期阈值，R1 是用 r 对同一 Q 的最后概率分类，保存 `K_ref=TP_ref+TN_ref` 与 `TP_ref`。

可行候选须同时满足 `TP+TN >= K_ref`、`TP >= TP_ref`。在可行候选中按 `(正确人数, TP, Precision, threshold)` 从高到低排序；人数精确比较，Precision 用整数比的精确比较，分母为零时为零，不四舍五入或增加容差。

如果最佳候选的正确人数与 TP 都与 R1 相等，返回原 r、状态 `unchanged_reference`，即使另一个阈值改变部分用户决策但计数相同，也不采用该变化。有至少一项严格增加才返回新阈值，状态 `selected`。r 本身在原网格中，因此正常输入必有可行解；无可行解是来源/实现错误，停止而非填造阈值。

输入须有限、概率在 [0,1]、标签二值、两类均存在、用户唯一且与获准成员一致、前缀完整、来源哈希匹配。非法输入拒绝，不当作无改善回退。

## 4. V02 固定两折交叉评价

每个外层 f=0..4、内层 j=0..2 的 H 独立按 user_id 排序，使用 `StratifiedKFold(n_splits=2, shuffle=True, random_state=30042+10*f+j)`。记录 scikit-learn 版本及实际成员。每次只在拟合半集 Q 选择阈值，在另一半 P 上评价，然后交换；总计 30 个评价半折，每个 H 用户恰好评价一次。

拟合半集 Q 上调用原早期阈值选择器，沿用 F-latency、early F1、speed、ERDE50、阈值的既有并列规则，产生 r。P 的标签和概率不得参与这一选择。这里重新拟合 r 只是对阈值流程的内部模拟，不改变五折最终早期阈值。

在完全相同的 Q 上确定三种决策：R1 用 r；旧策略 R2 用 `正确人数>=K_ref` 约束并优先 TP；新策略按第 3 节。三者均原样应用于 P，早期告警也用 Q 的 r。不得调用 entire-H 已存阈值，不对 P 再校准。

保存每个 Q/P 的成员、标签/概率来源哈希、阈值、选择表、P 决策和指标。只在本外层内部汇总三个 H 的评价结果；不同外层 S 有重叠，不把跨外层的用户重复记录冒充独立样本或 909 人 OOF，不跨外层汇集标签选择策略。

V02 是技术与内部泛化检查，不在新旧策略之间再进行自适应选择；无收益或负变化必须完整报告，但不改变第 3 节已锁规则。数据/数值/泄漏检查失败则停止；技术通过可继续 V03。本规则无隐藏晋级门槛，不根据结果追加候选。

## 5. V03 实际 C 校准与五折锁

每折使用已有最终 A 三种子平均 C 概率，r 直接采用对应 v1 第二锁的 R1 `threshold_early`。先核验 C 集合、bundle 文件哈希、模型及运行来源；重算 R1 计数应与 v1 校准记录一致。然后按第 3 节只选择新的最终阈值。

保存完整 201 点搜索表、约束参考、选中/回退原因、新 `threshold_final`、未变的 `threshold_early`、用户与标签角色、v1 父锁和模型/预测/协议/新代码哈希。五份子锁完成后再生成绑定全部子锁的总锁。

不将 H 的数值阈值移植到 C，不重新训练，不改变种子权重，不增加校准模型，不把不同外层 C 混合。读取 T 内容或生成新测试决策的入口，在有效五折总锁之前必须拒绝。

## 6. V04 一次评价、比较及成功定义

对象 ID：`ACC_V2`；比较对象为 v1 同概率 R2、R1 和历史 R0。每个用户仅在其原外层测试一次，合并覆盖同一 909 人。保持三种子概率不变；所有早期决策、告警位置和早期指标应与 v1 R1/R2 完全一致。各折、汇总及固定集成阈值下的单种子描述均保留，不选最佳种子。

主比较 `ACC_V2_vs_R2`：报告是否改善准确率，以及召回、误报和漏报的代价。另报告 `ACC_V2_vs_R1` 与 `ACC_V2_vs_R0`，不交换主要比较对象以挑有利结论。

对每个比较单独分类结论：Accuracy 与 Recall 都严格增加才称“双提升”；Accuracy 增加且 Recall 持平称“准确率提高、召回持平”；一升一降称“取舍变化”；其他情况照实报告。不能把校准集的双约束写成测试保证，技术验收不以性能提高为前提。

分类指标、混淆矩阵和早期指标全部复用原实现。用户级配对 bootstrap 固定 2000 次、seed=42、95% percentile 区间，每次两组共享用户索引，单一类别抽样跳过且报告有效次数，不补抽；三组比较均为描述性，不宣称新的确认性显著性。区间以既有模型及本次阈值为条件，不包含重训/重选不确定性。

五锁齐备后的第一次评价生成封存报告；后续仅允许对相同输入和锁作只读重放。不得利用外层结果调整阈值、规则、模型或数据角色。
